# Architecture

Corrective response to contingencies on transmission grids, with GENCO validated as a fast evaluator (IEEE 14, 30, 57 and 118).

```
Browser (React + Vite, `interface/`)
   │  solver adapter (`src/solver/`)
   ├── local DC (JavaScript, always available)
   ├── backend  -> FastAPI (`backend/`): AC (Newton-Raphson), DC, corrective response, N-1 screening, repair and reconnection
   └── replay   -> precomputed results (single file, no backend; `npm run build:replay`)
GENCO (`models/`, `backend/tools/genco_screening.py`, `backend/tools/genco_verifica_planos.py`): offline validation on line outages (`docs/GENCO_VARREDURA.md`) and as a verifier of the corrective plans (`docs/GENCO_VERIFICACAO.md`)
```

## Views of the diagram: DC | AC | GENCO
A selector in the sidebar chooses which method colors the diagram (the three stages of the corrective response are always AC):
- **AC** (default): the backend; in the static demo, the intact network and every single-line outage are precomputed (`interface/src/data/genco_lines_<network>.json`).
- **DC**: local JavaScript, instant, no losses; always available and the fallback when the backend is down (the button shows `AC*`).
- **GENCO**: what the authors' checkpoint estimates for the same state (AC-OPF base dispatch, one line out, no redispatch). GENCO (PF mode) predicts only the bus voltages; the line flows, the line loading and the reference-bus generation are computed from them with the same admittances as the AC, and the other generators keep the dispatch that is an input of the model. Measured on IEEE 118 (177 outages): mean loading error 0.10 % points, mean active-flow error 0.21 MW per line, reference-bus generation error 4.6 MW on average and 80.6 MW in the worst outage. It is precomputed (GENCO needs torch, which the backend does not have), so it is enabled for the intact network and for single-line outages that do not island buses; a chip shows the loading error and the reference-bus generation (GENCO vs AC) for the state on screen. Generated by `backend/tools/export_genco_lines.py`.

## What the operator does
1. Marks **faulted lines and/or buses** in the diagram.
2. **Analyze faults**: the system shows the pre-fault, post-fault and **with-plan** states. The generation is redistributed using its headroom and, if overloads remain, the plan combines redispatch and the **minimum load shedding** (any load; it maximizes the load served), verified by the AC power flow. The voltage is reported and, on IEEE 118 (replay), plans that end with voltage out of range go through the generator voltage adjustment made by GENCO-OPF (`backend/app/voltage.py`, `docs/TENSAO_GENCO_OPF.md`).
3. **N-1 screening**: every line and bus, sorted by severity, with the GENCO estimate.
4. **Repair and block reconnection**: repair order, plan recomputation after each repair and load reconnection in blocks, each block verified by the AC; energy not supplied (ENS) with synthetic times.

## Design decisions
- **Meshed transmission** has no normally open branches (0 of 186 lines in IEEE 118); the available resources are redispatch and load shedding.
- **Base dispatch** of IEEE 118: PowerModels AC-OPF (Pg and Vm), so the base case respects the limits.
- **The reference bus** absorbs the imbalance and the losses; only the reference island is energized.
- **The final plan is always confirmed by the AC**; GENCO enters as a screening step (it improves on the DC, but is still weak at the 100% limit).
- **Contract** between interface and backend: `docs/CONTRATO_API.md`. Swapping the evaluator (AC → GENCO) does not change the contract.

## Where everything lives
| Folder | Content |
|---|---|
| `interface/src/solver/` | Backend client, replay, pure display functions (corrective, screening, reconnection) |
| `interface/src/components/` | Diagram, panels (corrective, screening, reconnection), sidebar |
| `backend/app/` | `acpf.py` (AC/DC), `evaluate.py`, `corrective.py`, `voltage.py`, `screening.py`, `recovery.py`, `main.py` (API) |
| `backend/tools/` | Case and replay export, GENCO measurements |
| `models/` | GENCO checkpoints (authors' checkpoints for 14, 30, 57, 118, 500, 2000, 10000 buses; our N-10 and reduced IEEE 118 models; the OPF checkpoint) |
| `configs/`, `tools/` | Data generation and GENCO training; Windows fixes |
